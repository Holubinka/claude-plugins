# hook-guardrails

Two shell hooks for two mistakes a prompt cannot reliably prevent. **The only plugin here that runs code on your machine without being asked** — read both scripts before installing it.

```sh
/plugin install hook-guardrails@dev-workbench
```

## What it does

| Hook | Event | What it stops |
| :--- | :--- | :--- |
| `block-protected-push` | `PreToolUse` on `Bash` | A push that lands on `main`, `master`, `develop` or `release/*` — including a bare `git push` whose upstream silently resolves to one |
| `scoped-lint-fix` | `PostToolUse` on `Edit`/`Write` | A whole-repository format run triggered by editing a single file. It formats that file and nothing else |

## Why these two are hooks and not advice

`docs/security.md` in this marketplace says to prefer a skill over a hook, and that is the right default. Both of these are the exception for the same reason: **the thing that goes wrong is not something the model got wrong.**

**The bare push is the case worth the whole plugin.** Branching with `git checkout -b feature origin/main` sets the branch's upstream to `main`, so a later plain `git push` lands on `main` with **nothing in the command text to grep for**. The command is correct. The instruction was followed. The destination is a fact about the repository that neither the model nor a reviewer of the command can see. Only something that can resolve the upstream at call time can catch it.

**The whole-repository format is invisible in the moment.** The tool reports success, the edit looks right, and the unrelated files it also rewrote show up later in a diff nobody can explain. One incident touched four unrelated files and needed a revert.

## Both are guardrails, not controls

**They fail open.** Missing `jq`, missing `git`, an unresolvable destination — each of those lets the call through with a note on stderr, never a refusal.

That is deliberate and it is the opposite of `sdd-engineering`'s write gate, which refuses everything when `jq` is absent. The difference is what refusing costs: refusing a write you cannot verify is safe, and refusing **every Bash command** in the session because a dependency is missing makes the plugin unusable. **A hook people disable protects nothing**, so the failure direction has to be the one nobody turns off.

They are also not a security boundary. Anything with a shell can push wherever it likes. These close a slip, not an adversary.

## Escape hatches, and why they are visible

| Variable | Effect |
| :--- | :--- |
| `HOOK_PROTECTED_BRANCHES` | Space-separated patterns, replacing the default `main master develop release`. A pattern matches the branch and everything under it, so `release` covers `release/2.1` |
| `HOOK_ALLOW_PROTECTED_PUSH=1` | Lets one push through, and says on stderr that it did |
| `HOOK_SKIP_LINT_FIX=1` | Turns the formatter off |

**A gate with no escape hatch gets deleted the first time it is wrong during an urgent push**, and an override nobody can see is worse than no gate at all. Both of these announce themselves when used.

## What `scoped-lint-fix` will not touch

It resolves **one formatter for one file** from configuration that is actually present — Biome, then ESLint and Prettier separately, then ruff or black, rustfmt, gofmt. If none resolves, it exits silently. **Nothing is ever installed**, and no formatter is assumed: reformatting a file to a style the repository does not use is worse than leaving it alone.

Skipped outright: anything under `node_modules`, `dist`, `build`, `out`, `.next`, `coverage`, `vendor`, `target`; minified files and lockfiles; and **any file whose first five lines carry `@generated`, `Code generated by`, or `DO NOT EDIT`** — a generated file is not yours to reformat, whatever its extension says.

The project root is resolved **from the edited file**, walking up to the git root or the nearest manifest — never from the working directory. Falling back to the working directory is how a file gets formatted to the rules of whatever project the session happens to be sitting in.

## Verify it before you trust it

```sh
bash scripts/selftest.sh
```

Eighteen cases in a throwaway repository it creates and removes: the explicit pushes it must refuse, the ones it must let through (including `echo "git push origin main"`, which a naive substring match refuses), **the bare push whose upstream resolves to `main`**, and every skip rule in the formatter with a stand-in binary so the happy path is exercised rather than assumed.

Two of the cases exist because the self-test found real bugs during development: the formatter went through the package runner where only the `.bin` shim existed, and the project root fell back to the working directory outside a git repository. Both were caught by running it, and neither would have been caught by reading it.

## What it will not do

| Not this | Why |
| :--- | :--- |
| Block anything but a push | `PreToolUse` sees every Bash call and returns 0 for all of them except a push to a protected branch |
| Refuse when it cannot tell | An unresolved destination lets the push through. A hook that blocks on ambiguity is a hook people disable |
| Install a formatter, or pick a popular one | It reads what is configured. Nothing else |
| Format more than the file just edited | That is the incident it exists to prevent |
| Send anything anywhere | No network, in either script |

## Dependencies

None. `jq` and `git` are used where present, and both hooks degrade to doing nothing when they are absent.

## Compatibility

Claude Code >= 2.1.110. `bash`, and `jq` for reading the hook payload. The formatter also uses `timeout` when it is on `PATH` and runs without it otherwise.
